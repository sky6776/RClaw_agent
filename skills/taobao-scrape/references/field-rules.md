# 字段清洗规则（taobao-scrape）

首次清洗数据前通读一遍。所有规则源自桌面版抓取器多年实跑沉淀，但换算口径与平台无关，直接沿用。

## URL 模式速查

| 用途 | URL |
|---|---|
| 搜索 | `https://s.taobao.com/search?q=<关键词>` |
| 追加排序 | `&sort=sale-desc`（销量）/ `&sort=price-asc` / `&sort=price-desc` |
| 仅天猫 | `&tab=mall` |
| 商品详情（规范形式） | `https://item.taobao.com/item.htm?id=<商品id>` |
| 天猫详情 | `https://detail.tmall.com/item.htm?id=<商品id>` |

- 手机 WebView 里搜索 URL 可能被重定向到 h5/m 形态的等价页，属正常，以最终 URL 内容判定成败。
- 翻页：把已有 `page` 参数**就地替换**为新值，没有才追加（反复追加会产生 `page=2&page=3` 冲突）；翻页后商品 id 集合与上一页完全相同 = 已到底或不支持翻页，如实收尾。
- 商品 id 从链接里**带参数边界的** `id=` 参数提取（正则思路：`[?&]id=(\d+)`，防止咬到 `ali_trackid=2` 这类尾部含 id 的跟踪参数）；提取不到合格 id 的链接直接丢弃，不猜。
- **id 完整性**：snapshot 链接截断到 150 字符，可能正好切在 id 中间（如 `…&id=1234567890123` 被切成 `…&id=12`）。可信 id：位数 ≥10 且数字串不贴在截断边界末尾。可疑 id 的处理：先找同商品完整链接（同一商品的图片/标题链接常同 URL），找不到完整版就丢条并标注「链接截断」。**禁止用不完整 id 拼链接或当去重键。**
- 拿到可信 id 后按**原始域名**规范化 URL（丢弃截断的 tracking 参数）：域名含 `tmall` 用 `detail.tmall.com/item.htm?id=<id>`，其余用 `item.taobao.com/item.htm?id=<id>`。规范化不得改换域名——店铺类型要靠它判定。

## 三堵墙特征（URL + 页面文本）

| 墙 | URL 特征 | 页面文本特征 |
|---|---|---|
| 风控拦截 | 主机名或**路径**含 `deny`、`punish`、`deny_h5`（只看主机名和路径，查询参数 `?q=…` 不参与判定——搜索词本身可能含这些字母） | 「访问受限」「亲，抓不住你的手」；出现滑块/点选验证码组件 |
| 登录墙 | 页面被硬重定向到 `login.taobao.com`、`passport` 域名 | 弹出阻断式登录对话框/全屏扫码层，商品不可提取。注意：页面角落的「亲，请登录」导航链接不构成登录墙，商品可提取就继续采 |
| 空结果 | — | 「没有找到相关宝贝」「无匹配结果」 |

风控拦截后重试纪律：停止 → 等 ≥60 秒 → 最多再试 1 次 → 仍拦截则报告收工。连续触发会加重出口 IP 封锁，宁可今天少抓。

## 数值清洗

1. **价格**：取价格文本首行，剔除数字和 `.` 以外所有字符后转浮点。例：`¥1,299.00` → `1299.00`；`199元起` → `199`。区间价（如 `99-199`）取下限并在备注列标注「区间价」。
2. **付款人数**：淘宝列表页的「N人付款」是**付款人数**，不是销量件数，也不是月销——口径必须诚实。中文单位换算：`X.X万` → `X.X × 10000` 取整。例：`2.3万+人付款` → `23000`；`1500人付款` → `1500`；「暂无」→ 留空。只有页面文本明确出现「月销」「每月售出」时才另填月销量列。
3. **折扣**：仅有原价且 `原价 > 售价` 时计算 `round(售价 / 原价 × 10, 1)` 后拼「折」字。例：售价 129、原价 299 → `4.3折`。原价缺失就留空，不估。
4. **数量类字段（付款人数、评价数量）统一换算成整数**，不写「2.3万」，保证 CSV 可排序；**价格保留小数原样**（如 `99.90` 不写成 `99`），区间过滤和展示不得丢分位。

## 规格与套装识别（从标题/副标题提取，顺序拼接，用 ` / ` 分隔）

1. 容量/重量：数字 + `ml/mL/g/G/kg/oz/升/克/毫升`（含 `150ml+110ml` 组合形式）。
2. 件数：数字 + `件套/件装/套装/支装/瓶装/盒装/件`。
3. 乘式组合：`2*150ml`、`3x50g`、`2×100片` 形态整体提取。
4. 关键词规格（命中即收录，去重）：`大号 中号 小号 加大 加量 升级版 正装 旅行装 小样 体验装 礼盒装 礼盒 套盒 pro版 mini`。
5. 中文数字件套：`两件套 三件套 … 十件套`。

套装类型标签（按优先级取第一个命中）：`十件套 … 两件套`（中文数字或阿拉伯数字 + 件套）→ `单品/单件` → `礼盒装` → `套装` → `旅行装` → `小样/体验装`。全不命中留空。

## CSV 输出约定

- 表头（最小集在前，扩展列按实际有数据再加）：
  `商品标题,当前售价(元),销量文本,付款人数,商品链接,采集时间`
- 扩展列参考：`原价(元),折扣,月销量(件,页面明示才填),评价数量,店铺名称,店铺类型,店铺地区,促销标签,产品规格,套装类型`
- `销量文本` 保留页面原文（如 `2.3万+人付款`），换算值进 `付款人数` 列，两者并列便于核对。
- `店铺类型`按证据分级判定，**拿不到证据就留空，不猜**：
  1. 原始链接主机名含 `tmall`（如 `detail.tmall.com`）→ `Tmall`。
  2. URL 带 `tab=mall`（仅天猫搜索）→ 本轮全部 `Tmall`。
  3. 主机名是淘宝/天猫**共用**的移动详情域（`h5.m.taobao.com`、`item.m.taobao.com` 等）时主机名不可作证据 → 看商品卡片文本或详情页元数据里明确的「天猫 / Tmall」「淘宝」标记，按标记归类；标记缺失 → 留空。注意：淘宝商品也可能出现在 h5 共用域下，不能倒过来把共用域一律标 `Taobao`。
- `促销标签`：最多取 3 个、每个 ≤15 字，用 ` | ` 连接。
- **防公式注入**：标题、店铺、促销标签等来自页面的文本字段，若以 `=`、`+`、`-`、`@` 开头，写入 CSV 前在最前面加一个单引号 `'`——防止 Excel/WPS 把页面数据当公式执行。这是对不可信页面的强制处理，不是格式偏好。
- 文件用 UTF-8；尽量以 BOM（U+FEFF）开头（Excel 直开免乱码）。BOM 不可见、写入成功与否无法回读目检——没把握就如实标注「BOM 未确认」，不得声称「含 BOM」。
- `采集时间` 格式 `YYYY-MM-DD HH:MM`，同一任务内所有行用同一时间戳。

## 常见失败形态

| 形态 | 识别 | 处置 |
|---|---|---|
| 正文为空、snapshot 全是图片 | navigate 正文空且 snapshot 无 link | 截图留证；若用户要求且装有多模态读图能力，可用截图判读，报告里注明数据来自截图 |
| 结果页是"猜你喜欢"混排 | 卡片与关键词明显无关 | 停止采集报告异常，不要把无关商品充数 |
| 链接截断切进 id | 链接顶满 150 字符且数字串贴末尾 | 找同商品完整链接；找不到就丢条并标注「链接截断」，不用半截 id |
| 商品链接跳中间页 | 详情页 URL 形态异常（非 item/detail 域名） | 按 id 规范化 URL 重开一次，仍异常则标注「链接异常」 |
| page 参数无效 | 翻页后商品 id 集合与上一页完全相同 | 如实报告「已采集首页 K 个，此形态无法翻页」收尾，不堆页数、不编造已到底 |
