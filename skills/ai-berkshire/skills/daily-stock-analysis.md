# 交易日每日股票增量分析

对 $ARGUMENTS 中的一只或多只股票执行交易日增量跟踪。目标是快速回答“今天相对
上一次已验证结论发生了什么”，不是每天重写完整七步深度报告。

## 适用与升级规则

- 适用：定时每日跟踪、开盘前简报、收盘复盘、多只股票的日常监控。
- 先按日期从新到旧查找 `*-research-*.md`，逐个调用
  `skill__ai_berkshire__report_verify_pass`，将候选报告传入 `report`；只把退出码为 0、报告
  旁存在有效 `.audit-pass.json` 且证据账本哈希一致的最近深度报告作为研究锚点。
- 研究锚点有效后，再用同样方法查找锚点之后最近的 `*-daily-*.md` 作为增量比较
  起点；没有每日文件时直接从研究锚点开始。每日文件不得重置研究锚点的90天期限。
- 没有可确认准出的研究锚点、研究锚点的数据截止日距当前超过90天（不得用文件
  修改时间代替）、出现新年报/季报/业绩预告、发生并购或
  其他足以重写投资论文的重大事件时，停止增量路径并升级到
  `investment-research`；不得把未经核验的旧报告当作基线。

## 执行流程

### 1. 确认交易日和行情时点

1. 从交易所日历或配置的数据接口确认当日是否为A股交易日；仅凭“周一到周五”
   或脑算星期不能确认。日历来源不可用时明确报告“无法确认”，不继续发送交易日
   报告。
2. 调用 `skill__ai_berkshire__ashare_quote`，传入 `{"code":"{代码}"}`。使用输出中的“行情时间”作为价格时点；
   开盘前返回的通常是上一交易日收盘数据，必须写真实日期，禁止把系统日期或周日
   写成收盘日。
3. 多只股票可各用一个独立 Agent 并行取数，但交易日结论和工具路径由主 Agent
   只确认一次并传给各 Agent，不得每个 Agent 重复推算。

### 2. 只收集增量信息

从基线数据截止时点到当前时点检查：

- 最新价格、涨跌幅、成交与PE/PB等动态估值；
- 公司公告、监管披露、重大新闻；
- 行业或竞争对手中足以改变原论文的事件；
- 原报告的买入/减仓/风险触发条件是否命中。

静态股权、历史五年财务、护城河长文和管理层履历没有变化时只引用基线结论，
不要重新联网搜索、重写或重复审计。所有新增外部事实仍先写入
`tmp/{公司名}-daily-facts.json`，保留两个独立来源和正文文件。

### 3. 输出增量报告

写入 `reports/{公司名}/{公司名}-daily-YYYYMMDD.md`，包含：

1. 深度研究锚点、上一次增量报告及各自数据截止日期；
2. 本次行情的提供方时间戳；
3. 今日新增事实与事件；
4. 估值和触发条件变化；
5. 投资论文结论：不变 / 强化 / 弱化 / 需要完整重审；
6. 明确的行动建议及风险声明。

新增、可由外部来源直接核验的事实必须集中在唯一事实区：

```markdown
<!-- audit:scope:start -->
## 本次新增可核验事实
| 事实字段 | 报告值 |
|---|---:|
| 2026-07-31收盘价 | 6.30元 |
| 2026-07-31总市值 | 302.60亿元 |
<!-- audit:scope:end -->
```

模型估值、行动阈值和基线中未变化的历史事实不重复放入本次事实区。

### 4. 一次性准出

严格按以下顺序执行；`lint` 通过前不生成审计包：

```text
skill__ai_berkshire__report_lint
{"report":"skills/ai-berkshire/reports/<每日报告>"}

skill__ai_berkshire__report_extract
{"report":"skills/ai-berkshire/reports/<每日报告>","output":"skills/ai-berkshire/tmp/{公司名}-daily-audit.json"}
```

从前面建立的增量事实账本复制抽中事实的两个来源字段。对联网工具保存的每份页面
正文执行 `source-snapshot`，把命令打印的绝对快照路径和 SHA-256 填入审计包，
然后依次运行：

```text
skill__ai_berkshire__report_preflight
{"results_file":"skills/ai-berkshire/tmp/{公司名}-daily-audit.json","report":"skills/ai-berkshire/reports/<每日报告>"}

skill__ai_berkshire__report_verdict
{"results_file":"skills/ai-berkshire/tmp/{公司名}-daily-audit.json","report":"skills/ai-berkshire/reports/<每日报告>"}
```

预检失败时一次修复完整错误列表。若 `lint` 已通过却仍抽到日期、年龄、阈值等
非事实，停止改报告刷新样本并报告工具缺陷。只有 `verdict` 返回【准出】并自动
生成 `.audit-pass.json` 准出凭证后才能发布。

## 多股票交付

每家公司独立生成并准出报告；全部完成后由主 Agent 汇总一条简报并逐份发布文件。
某家公司失败不得用另一家成功结果掩盖，必须明确列出未准出的公司和原因。
