# 定时任务（cron）设计模式与技巧

用户通过 `cron_add` 创建定时任务时，常提出调度系统无法原生表达的执行条件。本技能记录如何用「消息内嵌条件」等方式绕过限制，构造可靠、可复用的定时任务，尤其针对投资分析类（A股交易日过滤、黄金行情、持仓盈亏上下文）等高频场景。

## 核心限制（必须知道）

`cron_add` 的调度能力有限：
- `schedule_type` 仅支持 `daily`（每天某时刻）和 `weekly`（指定周几某时刻）。
- **不支持**：仅交易日、节假日过滤、交易日历感知、条件触发、跨时区自动换算、月末/季末等复杂日历。
- 任务即「到点发送一段固定 message 文本」，由接收到消息的 Agent 在运行时解释执行。因此条件逻辑必须写进 message，而非依赖调度器。

## 关键技巧：消息内嵌条件（Trading-Day Filter 等）

当用户要求「仅交易日 / 仅工作日 / 节假日除外」执行时：
1. 调度仍设为 `daily`（或 `weekly` 去掉周末）。
2. 在 message 开头嵌入一段判断指令，让运行时 Agent 先判断、后执行。

### A股交易日过滤模板（开头段）

```
今天是交易日吗？请先判断当前日期是否为A股交易日（排除周末和国家法定节假日）。
如果不是交易日，直接回复"今天非交易日，跳过分析"即可，不做任何分析。
如果是交易日，<这里写真正的任务指令>。
```

要点：
- 必须明确「排除周末和国家法定节假日」——运行时 Agent 否则可能只排周末。
- 明确非交易日的兜底回复，避免静默无输出让用户以为任务坏了。
- 交易日判断若需精准，可让 Agent 联网查当日是否为 A 股交易日（调休、临时休市）。

## 投资分析类任务的标准结构

复用以下结构可快速拼出可靠的投研定时任务 message：

1. **条件守卫**（可选）：交易日/工作日过滤段。
2. **技能指定**：明确点名要用的 skill（如 `ai-berkshire`、`analyze-gold-market`、`glmv-stock-analyst`），避免运行时 Agent 选错工具。
3. **分析标的**：股票代码+名称（如 海澜之家 600398、中国石油 601857），黄金则说明品种。
4. **用户上下文**：把会随时间变化但任务需用到的信息写进 message——持仓金额、成本、当前盈亏等，让 Agent 据此给出操作建议。
5. **输出与渠道**：说明结果通过哪个 channel 推送（QQ/napcat 等）。

### 示例：黄金行情 + 持仓操作建议

```
今天是交易日吗？<…交易日过滤段…>
如果是交易日，请使用 analyze-gold-market 技能分析当日黄金行情。
用户当前持仓信息：黄金持有约1017元，已亏损232元。
请结合当日行情和用户持仓盈亏，给出具体的操作建议（观望/加仓/减仓/止损等）。
分析结果通过QQ发送给用户。
```

## 注意事项

- 用户口中点名的 skill 名（如 "ai-berkshire"）可能与 `skills_list` 中的实际 skill 名（如 `glmv-stock-analyst`）不同；创建任务时如发现名字对不上，应向用户确认真实意图，别默默替换也别默默忽略。
- 任务创建后用 `memory` 记一条任务摘要（时间、技能、标的、渠道），方便后续增删改时回溯。
- 删除任务用 `cron_remove(job_id=...)`；删除后同步清理对应 memory 条目。
