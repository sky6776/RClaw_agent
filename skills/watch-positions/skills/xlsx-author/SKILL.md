# xlsx-author

交付物是 Excel 工作簿时用本技能。工作簿用 Python/openpyxl 构建,用本技能自带的
recalc 脚本校验;本环境没有活的 Office 应用。

这里的规范是各产出技能的排版仲裁标准:其他技能的排版指令与本文件冲突时,以本文件为准。

## 输出语言

工作表名、表头、标签、单元格批注、`来源` 工作表与交付消息都跟随**用户的对话语言**,
不是模板语言——中文提问产出中文工作簿,英文提问产出英文工作簿。请求定不了语言的,
用 `zh-CN`。**一个工作簿一种语言**:中文工作表名不配英文列头。

单元格批注里的溯源标签跟随工作簿语言:中文簿用 `[披露]` `[测算]` `[预期]` `[推断]`
`[媒体]`,英文簿用 `[Reported]` `[Est.]` `[Consensus]` `[Inferred]` `[Media]`。
只用这些字面量——`[已披露]`、`[一致预期]` 之类改写在所有下游检查里都视同未标注。
术语两种语言下都保留源语言(口径、归母、报告期)。

## 输出契约

- **写到调用方收集交付物的地方。** 用户给了路径用用户的;否则用会话已建立的交付目录
  (工作目录里通常有一个,先看再猜);否则工作目录本身。写到调用方读不到的地方,
  等于没写。
- **文件名与工作簿同语言。** 回答「帮我给比亚迪搭一个 DCF」给出
  `002594_DCF_Model_2026-08-11.xlsx` 是半翻译交付,哪怕簿内每个表名都对;文件名是
  用户看到的第一样东西。代码、日期等标识符保持原样(`比亚迪_002594_DCF模型_20260811.xlsx`)。
- **收尾前列目录确认文件在。** 构建脚手架——生成脚本、临时副本、重算产物——放进一个
  之后删掉的子目录,绝不与交付物并排。生成工作簿的脚本是最常被留下的那个:它再小、
  再能说明你做了什么,也是脚手架——打开目录的读者分不清哪个文件才是交付物。
- 最终消息里**在正文中写明工作簿完整路径与一句内容概括**,各恰好一次。不得再附
  裸路径、Markdown 链接、路径清单,也不引用构建脚本/临时副本/重算产物等脚手架。

## 如何构建

写一个短 Python 脚本用 shell 运行,用 `openpyxl`(纯 Python,Windows/Termux 均可
`pip install openpyxl`):

```python
from openpyxl import Workbook
from openpyxl.styles import Font, PatternFill

wb = Workbook()
ws = wb.active; ws.title = "Inputs"
ws["B2"] = "Revenue"; ws["C2"] = 1_250_000_000
ws["C2"].font = Font(color="0000FF")           # blue = hardcoded input
calc = wb.create_sheet("DCF")
calc["C5"] = "=Inputs!C2*(1+Inputs!C3)"        # black = formula
wb.save(f"{DELIVER}/model.xlsx")   # DELIVER = 交付目录
```

## 规范

- **字体颜色承载语义——四种颜色,不是三种。** 蓝色 `#0000FF` = 硬编码输入。黑色 = 公式。
  绿色 `#008000` = 跨工作表链接。紫色 `#800080` = **同**表纯引用无计算(`=B9`)。
- **填充色**:`#1F4E79` 表头(白色粗体字),`#BDD7EE` 分组带,`#D9E1F2` 输入块,
  `#F2F2F2` 中性。调色板到此为止。
- **边框强制**且承载语义:分节标题上方 1.5pt,小计下方 1.0pt,内部网格 0.5pt,
  总计下方双线,最后一个历史列与第一个预测列之间细竖线。
- **数字右对齐,文本左对齐。** 表头与其列对齐。
- **计算格不得有硬编码。** 每个计算格是公式;每个输入在 Inputs 页。
- **公式里敲死的数字仍是硬编码——进了公式不等于洗白了。** `=6173.8194+1.1194` 看着合规
  但不是:两个数字是取回值,却没有自己的单元格,既不能标蓝,也不能带自己的来源批注,
  读者改一个也看不到模型联动。这是上一条规则的漏洞,而它读起来像满足了规则——
  「这个格*是*公式」。把每个取回值放进自己的输入格、带自己的批注,公式引用这些格:
  `=Inputs!B12+Inputs!B13`。
  - 公式里唯一允许的字面量是**读者永远不会想改的结构常数**:单位换算(`/10000`)、
    期数(`/12`、`/4.33`)、百分数转小数(`/100`)。字面量带来源、带日期、带口径,
    它就是输入,不是常数。
  - 破绽是**公式里的多小数位字面量**——`6173.8194`、`0.0865`。结构常数短而圆。
- **在本簿内从其他格推导出的值是计算格,不管它是「什么」的值。** 取回输入的豁免覆盖
  你取来的,不覆盖你从它算出来的:收入−成本的毛利润、基准×0.7 的下行情景、除出来的
  净利率、小计、同比。读者改动来源格而你的数字不动,模型就是装饰。
  **破绽是无批注格里的全精度浮点**——`722.4499999999998`、`0.09799999999999999`。
  读原始值,不看显示:观测到的每一例都藏在 `#,##0.0` 或 `0.0%` 格式后面,这正是
  从没被抓到的原因。**带批注**格的全精度不同且没问题——供应商 API 就这么返回字段,
  取回的涨跌幅 `3.357724446617073` 是忠实而非计算。
- **每个硬编码输入带来源批注**:`Source: <系统或文档>, <日期>, <参考>, <URL>`。
  计算格带公式,公式即其溯源——计算格上出现来源批注,说明里面藏着硬编码。
  「发布主体 · 系统名」填**实际调用的数据商**(同花顺 iFinD / 万得 / 东方财富)+
  所取数据,不填 MCP server 名或工具名;无具体公开页面时 URL 段整段省略。
- 会出现在汇报或备忘里被引用的值,建**命名区域**。
- **平衡校验。** 加一个 Checks 页(资产负债平衡、现金流对到现金等),显式出 TRUE/FALSE。
- **一簿一模型。** 未明确要求不追加到既有工作簿。

## 两类工作簿,两种溯源载体

上面的逐格来源批注是为**模型**写的——几十个判断或取回的输入,每个值得一条批注。
它扩不到本技能造的另一类东西上:1,200 格的筛选结果带不动 1,200 条批注,实践中就会
一条都不带。先定要建哪一类,再用那一类的载体;两者都是强制的,不因用了另一个而豁免。

**Class A — 模型或测算簿。** DCF、LBO、增厚/摊薄、三表联动、资金来源与用途、现金流
预测、差异桥。输入少,公式多。载体:**每个蓝色硬编码输入的逐格 `Source:` 批注**,
外加 Inputs 页与 Checks 页。

**Class B — 筛选、名册、快照簿。** 基金筛选、标的名册、批量风险扫描、盘中快照、
多指数分位表。取回行多,公式少或没有。逐格批注不可行,**这里不要求**。载体改为:

1. **`来源` 工作表,就是这个表名**——全簿最后一个标签页。每个不同来源一行,编号供
   数据行指向:

   | 编号 | 一手/二手 | 发布主体 · 文档或系统名 | 指标/字段 | 日期(发布日) | 检索于 | URL |
   |---|---|---|---|---|---|---|
   | 1 | 一手 | 同花顺 iFinD · 债券静态档案 | 债券简称/发行人/到期日([债券代码]) | — | 2026-08-12 | — |

   「URL」只有两种诚实填法:访问过具体页面就填那一页;**接口供数、无公开页面时留空
   (填 `—`)**。不拿机构首页补位。

2. **每个数据页加 `来源编号` 列**,携带该行来自的 `编号`。一行来自两个来源就都写
   (`1,3`)。它替代逐格批注:值到源的映射得以存活,代价是一列而不是每格一条批注。

3. **`来源` 页顶部或底部放 `口径与局限` 块**:实际执行的筛选条件(可能与用户要求不同,
   要说明)、引擎无法执行的条件、滞后字段的报告期,以及未解析项的三种覆盖状态
   (`有记录`/`检索范围内未发现`/`源不可用`)。这就是覆盖度区块;工作簿没有别处可放。

Class B 簿内的**判断型**输入——你选的分摊驱动、你设的阈值、你给的权重——仍是 Class A
格:给 `Source:` 批注并标 `[测算]`,因为它是你的,不是取回的。

**四种字体颜色同样按类适用。** 蓝不是装饰:它是复核者追查「哪些格欠来源批注」的索引。
Class A 把**每个**硬编码输入标蓝——有批注无蓝色的模型藏起了自己的索引;Class B 不逐格
上色,因为 `来源编号` 列已承载映射。Class B 簿内的判断格照常标蓝。

## 交付前重算(强制)

openpyxl 写入的是公式字符串,不求值。交付任何工作簿前,运行本技能自带的 recalc 脚本
(位于本技能目录下 `scripts/recalc.py`):

```bash
python <本技能目录>/scripts/recalc.py "$DELIVER/model.xlsx" 30
```

脚本把工作簿复制到临时目录,经无头 LibreOffice 重算每个公式,扫描 Excel 错误
(`#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#NULL!`、`#NUM!`、`#N/A`)。**你的文件
不被修改**——LibreOffice 的 OOXML 往返有损,会丢承载来源引用的单元格批注。确要重算后
的文件,传 `--write-back`,会先写 `.bak`。

```json
{"status": "success", "total_errors": 0, "total_formulas": 42}
```

退出码有语义,`&&` 链安全:`0` 成功,`2` errors_found,`3` recalc_unavailable,`1` 硬失败。

- `"status": "errors_found"` → 修掉 `error_summary` 列出的每一处,重跑到 `"success"`。
- `"status": "recalc_unavailable"` → LibreOffice 未安装(Windows 未装或 Termux 均如此),
  **没有任何公式被真正求值**;脚本只跑了静态 lint(断链的跨表引用)。**此状态不是通过。**
  修掉所有 `BROKEN_SHEET_REF`,再做下面的替代检查,然后才能交付。

### recalc 不可用时(强制的替代检查)

干净的静态 lint 证明不了公式算出的是想要的值。不得把 `recalc_unavailable` 当验证。
改用 openpyxl 重新打开工作簿,在 Python 里:

1. **引用检查** — 对每个公式格,断言公式串指向你想要的格(如第 `r` 行的利润率必须是
   `=F{r}/C{r}`,不是相邻行)。差一行引用是最常见的 openpyxl bug,静态 lint 看不见。
2. **重算** — 在 Python 里从原始输入独立计算每个派生值,确认算术合理(无除零、无单位
   错配、结果在合理范围)。
3. **恒等式检查** — 断言该模型类型按定义必须成立的关系(毛利率 > 营业利润率 > 净利率;
   资产负债平衡;来源 = 运用;分部加总 = 总计)。

然后在交付消息里**明说局限**:跑了哪些检查、公式未经电子表格引擎求值、请用户打开确认。
绝不仅凭静态 lint 把工作簿描述成「已验证」或「已审计」。
