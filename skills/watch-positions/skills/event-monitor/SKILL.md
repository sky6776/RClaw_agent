# Position Event Monitor

标的名单的事件驱动扫描。产出按严重度排序,不按名单顺序。

## Workflow

### Step 1: 定范围

读清单(或直接收名单)。默认窗口:清单文件 `notes` 里记有上次扫描日期则自那以后,否则最近
5 个交易日。输出头部确认窗口。

### Step 2: 逐只扫描——披露事件优先

每只,按此顺序(合并去重):

1. **公司事件** — MCP:`wind-stock__get_stock_events`(`question` = 简称 + 单一事件类型 + 窗口;
   **限售解禁不在此工具**,见下条):业绩预告/快报、增减持、分红、股权激励、再融资、
   股权质押公告。这是结构化事件表(带解禁日期、质押公告日、重组进度等列),优于在公告正文
   里语义检索——一次一种事件类型,多主题堆叠会漏匹配。兜底轨:无结构化事件表,以
   `announcements` 公告标题按事件类型筛选替代;增减持结构化记录 `源不可用`。
2. **风险面** — 股权质押:MCP `hexin-stock__get_risk_indicators`(`质押比例`,存量截面)或
   `get_stock_financials`(质押比例、商誉金额);兜底轨 `events`(东财质押比例截面)。
   涉诉/失信/行政处罚两轨都不覆盖:如实记 `源不可用`,建议需要时用通用网络搜索单独深挖。
3. **新闻/公告** — MCP:`wind-docs__get_financial_news` / `wind-docs__get_company_announcements`
   (无日期参数,窗口写进 `query` 后自筛);第三方信息按档位召回走
   `finance-search__finance_search`(`date_from`/`date_to`)。兜底轨:`news`(东财个股新闻)+
   `announcements`(巨潮公告)。

一次查询一个问题(用简称,不带内联代码)。零事件的标的在「检索范围内未发现事件」一行里
报告,不静默省略。

### Step 3: 分级

- **🔴 高 — 需要立刻看**(决策前须澄清): 立案调查/行政处罚、核心高管被查、违约、非标审计
  意见、大股东质押爆仓风险、业绩预告大幅低于/高于预期。
- **🟡 中 — 需要跟踪**(记录并观察): 大股东减持计划、限售解禁临近(30 天内)、再融资、
  重大合同、诉讼进展、评级变动、龙虎榜异常席位。
- **⚪ 低·信息 — 知悉即可**: 常规分红、例行公告、小额回购进展。

多个事件竞争注意力时,按「多直接地强迫一个决策」排序:立案调查/处分 > 业绩预告变脸 >
大股东减持/质押平仓风险 > 限售解禁 > 龙虎榜异常席位——分级定档,此序定呈现先后。
严重度对照持仓相关性判断:10% 权重上的常规事项,重于 0.5% 权重上的花边头条。
评的是事件,不是持仓;🔴 最多三条置顶,其余进正文。

### Step 4: 输出

默认会话内 Markdown。用户要文件:监控表走 `xlsx-author`(**Class B** 工作簿——`来源` 工作表
+ 事件行的 `来源编号` 列,窗口与三种覆盖状态写进口径与局限块);事件简报走 `report-render`
(先 `read {skills_dir}/watch-positions/skills/report-render/SKILL.md`;其内置平台门禁,Termux
自动降级 Markdown)——绝不手搓 PDF,手搓不会把 `[n]` 做成链接注记。

```
**事件监控 — [清单名]**(窗口: [起]—[止], 检索于 [时间戳])

🔴 高 [标的] — [事件一句话] · [日期] [n]
   影响: [一两句,含数字须有来源;自行推导的比例标 [测算],自行的判断标 [推断]]
🟡 中 ...
⚪ 低·信息 [标的A/B/C]: [归并的一行]

检索范围内未发现事件: [标的列表]

**覆盖范围与局限**: 检索于 [时间戳],窗口 [起]—[止]。数据轨: [MCP 同花顺+Wind / 东财兜底]。
覆盖清单内 [N] 只的公告、公司事件、风险面指标与新闻。本次未覆盖: [源不可用的标的/检查项
与原因,以及它们本应覆盖的内容;(兜底轨)增减持结构化表、涉诉/失信/行政处罚]。
"检索范围内未发现事件"指上述源在该窗口内无记录,不等同于无事发生——公告与判决上网均有滞后。

## 来源
[n] 〔一手|二手〕发布主体 · 文档或系统名 · 日期(发布日; 检索于) · URL
```

### Step 5: Guardrails

- 绝不推断没有来源披露的事件;新闻里的传闻是 `[媒体]`,披露记录证实后才变 `[披露]` 并引用该记录。
- 写明扫描的确切窗口(传给垂搜的 `date_from`/`date_to`,或公告/新闻 `query` 里的日期短语)。
- 用户要定期扫描(每天收盘后/每周一早)时,用 RClaw 内置 `cron_add` 配置节奏并复述确认——
  不要默默承诺未来的扫描。
- 报错、超时、或不覆盖某类实体的源是 `源不可用`,要点名——不得折进「未发现」,那会虚增覆盖。
- `[n]` 与 `## 来源` 一一对应。`〔一手|二手〕` 强制;`二手` 写明转述的是什么。终端接口取数
  无独立发布日期的公告,标 `检索于 [date]`。
