# After-Close Recap

产出一份基金经理 3 分钟内能读完的复盘:什么动了、为什么、什么需要决策。

> **参考价:先用成交量过滤。** MCP `hexin-stock__get_stock_performance` 不剔除停牌日——
> 收盘被昨收顺延填充,只有成交量被清空(`\t` 或空串)。据此取的「上一交易日收盘」是顺延价:
> 数字对、基准日错、且毫无异样。成交量空白行不是交易日。兜底轨 `hist` 返回的停牌行同理,
> 先按成交量/是否缺行过滤再取参考价。

## Workflow

### Step 1: 装载标的集合,定窗口

- 读清单文件(`watchlists/<清单名>.json`);没有就问一次名单。
- 通过一次实时行情/时间查询确认会话日期——绝不凭记忆假设「今天」。默认窗口是最近一个
  已完成交易日;「本周」「since <日期>」用日频数据支持。

### Step 2: 拉涨跌——MCP 每标的一次调用;兜底轨逐只 `hist`

- MCP:`hexin-stock__get_stock_performance`(`codes` + `indicators=收盘价,涨跌幅,成交量,换手率`
  + 日期区间;按交易日历过滤),主体用简称,回读 `证券代码`。
- 兜底轨:`ak_fallback.py hist --code ... --start ... --end ...` 逐只拉,自行计算单日涨跌幅
  (标 `[测算]`,基于东财收盘价)。
- 缺失或停牌的标的如实报告,永不补数。

### Step 3: 大盘与板块背景

- 大盘:MCP 用 `hexin-stock__get_stock_performance` 传指数代码(如 `000300.SH`)取窗口序列;
  兜底轨用 `index_hist`。单日截面 PE/PB:MCP `hexin-index__index_data`;兜底轨无此数据,
  覆盖度区块记 `源不可用`。
- 板块背景优先 `hexin-index__sector_data`(成份区间涨跌幅、市盈率(TTM,整体法)、总市值、
  成份股个数)——它是真正的板块聚合,不是近似指数。**主体必须同时点名板块与分类**
  (`食品饮料板块(申万行业)`);裸行业名返回空表,看起来像「没有」而实为「没查到」。
  回读板块名称确认;解析不了就说明板块聚合不可用、退回指数,不得把指数当板块呈现。
  兜底轨无板块聚合:记 `源不可用`,用指数对照替代并明说。

### Step 4: 异动归因

每个超出 max(±2%, 2×基准涨跌) 的标的:

**先确认这个异动对该标的真的异常。** MCP:`hexin-stock__get_risk_indicators`(波动率(年化)、
区间最大回撤、BETA),回读窗口;−4% 在年化 60% 波动的标的是常态内,同样 −4% 在 15% 波动的
标的就是事件。兜底轨:用近一年 `hist` 自算年化波动率(标 `[测算]`),回撤/BETA 记 `源不可用`。
常态离散度内的异动如实报常态,**不给叙事**——给噪音发明原因正是本步骤要防的失效模式。
对比是 `[测算]`;波动率/回撤/BETA 输入是 `[披露]`(自算则 `[测算]`)并陈述窗口。BETA 还能
说明大盘本身解释了多少。

过了这道门槛的:

1. **先查披露事件**:MCP `wind-docs__get_company_announcements`(公告)与
   `wind-docs__get_financial_news`(新闻)——两者都无日期参数,把窗口写进 `query` 后自筛;
   第三方报道走 `finance-search__finance_search`(`date_from`/`date_to` 真过滤)。兜底轨:
   `announcements`(巨潮公告列表)与 `news`(东财新闻),窗口在脚本内过滤。
2. **公司事件**:增减持/分红/股权激励/再融资 MCP 走 `wind-stock__get_stock_events`
   (一次一种事件类型);**限售解禁**两家都没有结构化表——MCP 走公告正文找解禁日期与数量;
   兜底轨用 `events`(质押比例 + 解禁表),增减持结构化表记 `源不可用`,以公告标题筛选替代。
3. 披露记录解释不了的,才给带标签的假设:板块贝塔、同业联动、资金/技术面。标 `[推断]` vs
   `[披露]`,带 `[n]`。相对基准差值是我们的算术,标 `[测算]`。

小异动不归因——「在指数波动范围内」就是完整答案。

### Step 5: 组装复盘

默认短格式:会话内 Markdown。用户要文档时:PDF/Word 走 `report-render` 技能(先
`read {skills_dir}/watch-positions/skills/report-render/SKILL.md` 再动手;该技能内置平台门禁,
Termux 上自动降级为 Markdown 文件交付)——绝不手搓 weasyprint/wkhtmltopdf/pandoc/裸
reportlab,那些不会把 `[n]` 做成 PDF 链接注记,引注点不动。多标的涨跌归因表走
`xlsx-author`。手搓 python-docx / docx-js 会丢标签配色、`[n]` 跳转与封面页。

```
**[日期] 收盘复盘 — [清单名]**(基准: [指数] [涨跌幅] · 检索于 [date] [时间] 收盘)

**需要关注**(最多 3 条 — 有事件、破位、或需要决策的)
- [标的]: [动作/事件一句话] + 我们的读法 [n]

**异动归因**
- [标的] [涨跌幅] vs 基准 [x%] `[测算]`: [披露事件 [披露] 或推断 [推断]] [n]

**其余持仓**: 一行带方向的汇总(如 "其余 12 只随指数波动 ±1% 以内")

**明日日历**: 财报、解禁、股东大会、宏观数据(仅列清单相关的)

**覆盖范围与局限**: 检索于 [date] [时间] 收盘。数据轨: [MCP 同花顺+Wind / 东财兜底]。
覆盖清单内 [N] 只的行情、公告、公司事件与新闻;停牌/无行情 [标的] 已如实标注。
本次未覆盖: [源不可用的项,如龙虎榜、融券余额、(兜底轨)板块聚合/增减持结构化表]。
"检索范围内未发现事件"指上述源在本窗口内无记录,不等同于无事发生。

## 来源
[n] 〔一手|二手〕发布主体 · 文档或系统名 · 日期(发布日; 检索于) · URL
```

清单带权重时,先给组合层面收益与最大贡献/拖累(组合收益是 `[测算]`,说明加权口径)。

**覆盖度标签就用 `覆盖范围与局限`,逐字。** 复盘可以把区块压缩成行文,但标签本身不改名:
`近期关注与局限`、`数据说明`、`局限性`、自编编号小节,在找覆盖声明的读者眼里都等于
**没有覆盖声明**。保留标签,结构随篇幅自便。

### Step 6: 溯源

- 每个价格与涨跌带 `检索于`(时间 + 时段:`检索于 [date] 15:00 收盘`)——盘中价的含义取决于此。
- 每个事件一个 `[n]`,映射到 `## 来源`。`〔一手|二手〕` 强制:交易所公告是一手,转述的
  新闻是二手并写明转述的是什么。数据 API 取的、无发布日期的行情,标 `检索于 [date]` 即可。
- 不同 `[n]` 的数量必须等于来源条目数;`数据来源见上` 不是引用。
- `[测算]` 与 `[推断]` 不因篇幅省略:否则读者无法把我们的算术与我们的解读从披露中区分出来。
