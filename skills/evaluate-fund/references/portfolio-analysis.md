1. 多基金比较口径
2. 当前持仓输入

## 1. 多基金比较口径

比较两只以上基金时，先建立统一字段表，再做计算。至少统一：

- 具体份额、币种、总回报/复权净值口径、数据频率与共同起止日
- 产品目标、正式基准、主动/被动属性、费用口径
- 当前经理任期、持仓报告期、披露覆盖率与数据获取日
- 共同区间内的两两收益相关性及样本数；短样本或恒定序列不强行解释相关性
- 同类产品只在同目标、同风险来源下排名；异类产品比较组合角色，不做总分排名

净值 CSV 的每一行必须同时含全部待比较基金的数值。不要用成立前数据填补较年轻基金，也不要把不同区间的 CAGR 并排当作共同期间表现。

`skill__evaluate_fund__compare_funds` 的 `benchmark_col` 是所有基金共享的基准，只适合相同目标的产品。基金正式基准不同时，先用共同日期比较绝对风险收益与两两相关性，再分别按自身基准计算 alpha、Tracking Error 和 Information Ratio。

## 2. 当前持仓输入

把标准化持仓保存为 UTF-8 JSON。所有比例均用小数，`0.125` 表示 `12.5%`。输入可采用以下两种方式之一：

- 权重模式：每只基金提供 `weight`，并可提供 `cash_weight`；合计不得超过 1，剩余部分记为“未配置”。
- 市值模式：提供 `base_currency`，每只基金提供已换算到该币种的 `market_value`，并可提供同币种的 `cash_market_value`；脚本按总市值归一化。可用 `market_value_currency` 显式标记，若与基础币种不同脚本会拒绝计算。

不要混用两种模式，不要用买入成本占比替代当前市值占比。

  "cash_weight": 0.10,
  "funds": [

### 字段规则

- `asset_allocation`、`exposures` 和 `holdings[].weight` 都是相对单只基金净资产的比例。
- 权重模式中的每只基金必须有正权重；零权重候选不要放入当前持仓。基金 `code` 必须用字符串保存，避免 `000001` 变成 `1`。
- 为国内当前持仓填写 `share_class` 和 `trading_venue`；`share_class` 使用 A/C/E/I 等实际份额类别，无独立份额类别时写“无”，`trading_venue` 使用“场内”或“场外”。同一产品同时有场内、场外实现方式时，填写用户实际持有的渠道。
- `skill__evaluate_fund__analyze_portfolio` 输出的 `fund_weights[].label` 使用“基金名称 [代码]”作为计算标签；同名不同代码的 A/C 等份额不会被误合并。生成持仓建议时不得直接复制这个简化标签，必须使用同一输出行的 `name`、`code`、`share_class` 和 `trading_venue` 组装“基金全称 [六位代码；份额类别；场内/场外]”。
- `exposures` 支持 `industry`、`sector`、`market_board`、`region`、`currency`、`style_size`、`style_orientation`、`duration_bucket`、`credit_quality`，以及非互斥的 `risk_tag`。
- `index_or_strategy` 用于聚合跟踪同一指数或采用同一策略的基金；主动基金可填写稳定且可验证的策略标签，不确定时留空并归入“未知”。
- 某维度存在基金级 `exposures` 时优先使用；否则脚本从已披露 `holdings` 推导。
- 单一互斥维度已知比例不足 1 时，剩余部分保留为“未披露/其他”，不得按已知持仓比例放大到 100%。
- `exposures.risk_tag` 或 `holdings[].risk_tags` 是非互斥标签，同一证券可有多个标签，因此风险标签合计可以超过 100%；存在基金级 `risk_tag` 时优先使用，避免和持仓标签重复计算。
- `risk_score` 仅接受 1–5；不同销售平台风险等级口径不一致时不要混合计算。
- 同一底层证券优先以统一大写 ticker 合并；缺少 ticker 时以名称合并，并在报告中提示名称匹配风险。

动态工具输出的 `target_gaps` 只计算距最近目标边界的差额，不等于交易指令；正数表示需增加到下沿，负数表示需降低到上沿。`limit_breaches` 是硬约束超限清单。建议区间必须结合用户期限、回撤承受力、税费、可交易性与应急现金另行判断。

`portfolio_summary.underlying_security_coverage` 是已列入 `holdings` 的底层证券占整个用户组合的比例；`underlying_security_uncovered_weight` 是基金权重中未出现在 `holdings` 列表的部分，可能包含基金内现金、债券、其他资产和未披露证券，不能全部称为“未知持仓”。用户组合顶层现金和“未配置”不计入后者。缺少 ticker 的证券按名称合并，输出会附带名称匹配警告；缺少名称和 ticker 的持仓会被拒绝，避免把多个未知证券误判为同一持仓。

## 3. 组合穿透解释

必须分别解释以下维度：

| 层级 | 维度 | 重点问题 |
|---|---|---|
| 产品 | 基金类型、经理、基金公司、指数/策略 | 是否存在同源管理或策略重复 |
| 资产 | 股票、债券、现金、商品、REIT 等 | 风险资产与流动性是否符合目标 |
| 权益 | 行业、板块、地区、币种、规模、价值/成长 | 是否由同一宏观或风格因子驱动 |
| 固收 | 久期、信用等级、利率/信用/流动性标签 | 名义分散是否掩盖同一信用风险 |
| 底层证券 | 总穿透占比、被多少基金重复持有 | 单一公司或发行人冲击会损失多少 |
| 数据质量 | 披露日期、已知覆盖率、未知比例 | 结论是否足以支持调整 |

基金数量不是分散度。报告至少给出最大单基金、前三大基金、标准化 HHI/有效基金数、最大底层证券、重复证券和主要未知比例。若不同基金披露日期相差较大，重叠只能视作披露时点估计。

## 4. 底层股票研究

### 4.1 研究范围

优先研究：

1. 每只股票型基金前十大持仓；
2. 单只占基金净资产 5% 以上的股票；
3. 被两只以上基金共同持有的股票；
4. 穿透后占用户组合 3% 以上的股票；
5. 存在财务、估值、治理、监管或流动性红旗的股票。

阈值用于控制研究成本，不代表低于阈值的持仓没有风险。完整持仓可得时仍应计算整体行业与证券集中度。

### 4.2 每只重点股票的最小证据集

- 业务构成、行业与主要收入/利润地区
- 最近年度和中期的收入、利润率、经营现金流/自由现金流趋势
- 净债务、利息覆盖、融资或稀释压力
- 估值指标及其口径；周期股不得只看静态市盈率
- 最近重大公告、治理/监管事项、核心正面和反面证据
- 在基金中的披露权重、在用户组合中的穿透权重、由哪些基金贡献

公司事实优先使用公司、交易所和监管披露。基金定期报告只证明报告期末持仓；除非基金公司提供更近的正式披露，不得写成“当前仍持有”。

### 4.3 从股票回到基金与组合

不要机械平均个股结论。按穿透权重判断：

- 高质量但高估值持仓主要增加估值压缩风险，不必直接否定基金；
- 多只基金重复持有同一公司或同一因子，会降低名义分散的有效性；
- 单一红旗公司的影响取决于穿透权重、基金调仓权限和披露滞后；
- 未披露部分较高时，结论应降级为情景判断，并明确需要的下一份报告。

## 5. 调整建议边界

将建议分成三类：产品本身不合格的“产品问题”、产品合格但组合重复的“组合问题”、产品与组合合理但不适合用户约束的“投资者不匹配”。输出“调整方向 + 渠道匹配的具体动作 + 当前值与建议区间/目标值 + 理由 + 优先级”，并说明调整前提、可能税费和复核日期。

涉及当前持仓时，建议必须能直接映射回持仓清单：

- 使用“基金全称 [六位代码；份额类别；场内/场外]”标识每只国内持仓，不得只写指数简称、资产类别、策略名或基金公司名。
- 将每只当前持仓拆成独立一行；不得在一个持仓单元格或动作单元格中合并多只基金。
- 同时填写当前占比或金额和建议区间或目标金额。使用“渠道匹配的唯一动作 + 调整结果”表达动作，例如“场外赎回，将占比从 12% 降至 0%–5%”或“场内卖出，将市值从 2 万元降至 1 万元以内”；不得只写“降低”“清理”“合并”，也不得把“赎回/卖出”等候选动作原样留给用户选择。只有核实转换资格和费用后才使用“转换”。保持不变时也要匹配渠道，例如场外写“保持当前仓位，既不申购也不赎回”，场内写“保持当前仓位，既不买入也不卖出”，并给出维持区间、观察期限或触发条件。
- 将“合并”“替换”“降低基金公司集中度”等组合动作拆成来源基金和目标基金各自的行，并在理由中说明这些行属于同一调整方案。例如，不写“合并A50 + 中证500 → 保留A500”，而分别写明 `{A50基金全称}`、`{中证500基金全称}` 和 `{A500基金全称}` 的退出、降低、保持或增加动作。
- 若目标基金不在当前持仓且尚未完成产品筛选，另起一行写“非当前持仓（候选待筛选）”，列出规模、类型、费用、久期或信用等筛选条件，不得杜撰基金名称或代码；问题类型仍按组合问题标注。
- 若名称、代码、份额类别或场内/场外身份未核实，标记“身份待核对”，只给核对后的条件式动作。

没有用户目标、期限或最大可接受回撤，即缺少这些个性化参数时，不得阻断逐只持仓的明确操作方向。声明中性默认假设后，仍应给出持有、暂停加仓、分批赎回/卖出、合并、替换或新增方向，以及理由、优先级、成本和触发条件；只有精确交易金额、精确目标比例和整体股债/现金配置改用区间或多情景方案。不得声称存在精确的唯一最优比例，也不得仅凭短期市场预测要求择时；先交付可执行建议，再用不超过三个问题收集信息以调整幅度。
