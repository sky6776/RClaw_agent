# 基金评估

默认聚焦中国境内公募基金，基于当前、可核验的数据评估基金和基金组合。把产品质量、组合中的作用、投资者适配度分开判断；不要只看近期涨幅、平台评级或单一排名。

## RClaw 路径与运行约定

- 启动前本 skill 会部署到 `agent/skills/evaluate-fund/`；结构化路径参数以 agent 根目录为基准。
- 使用 `{SKILL_DIR}=skills/evaluate-fund`，不要在路径参数前再加 `agent/`。
- 所有脚本入口都不得自行选择 Python、脚本路径或参数协议；读取本 Skill 后，由 Manifest 动态激活的专用工具负责定位脚本并直接启动进程。
- 把每次完整分析写到 `fund_analysis_output/{任务名}_{YYYYMMDD_HHMMSS}/`，至少包含 `report.md`；`{任务名}` 只使用基金代码、字母、数字、中文、连字符和下划线，移除 Windows 保留字符。不要把运行产物写回 skill 目录。

## 核心原则

- 先确认产品身份、份额、币种、注册地和基准；不要凭记忆认代码。
- 国内产品必须区分六位基金代码、A/C/E/I 等份额、场内/场外、ETF 与 ETF 联接；销售平台标签只作线索。
- 使用含分红再投资的总回报或复权净值；不要把分红、拆分或汇率差异误当成超额收益。
- 先核对策略有没有兑现，再评价收益；主动基金、指数基金、债券基金不能使用同一套阈值。
- 同时报告收益、风险、费用、实现方式、底层暴露和适配度；不以单一 Sharpe、星级或近一年排名下结论。
- 区分事实、计算、推断和条件性建议。数据不足就标记缺口，不补数。
- 对当前数据和投资判断必须联网核验并给出可打开来源；搜索摘要只用于发现来源。
- 当前持仓建议结合用户目标、期限、回撤承受力和实际占比；缺少这些个性化参数时不得拒答，先声明中性默认假设，基于已核验的产品与组合证据给出明确的持有、暂停加仓、分批赎回/卖出、合并、替换或新增方向，再用区间和情景说明调整幅度。

## 1. 选择任务模式

根据请求选择一种主模式，可组合使用：

1. **单基金体检**：评估产品质量与适合对象。
2. **多基金比较**：用统一口径比较两只以上基金，给出差异和条件性选择。
3. **当前持仓分析**：穿透多只基金，计算组合暴露、重叠、集中度和再平衡方向。
4. **股票持仓研究**：研究股票型基金的披露持仓和关键底层公司。
5. **份额/交易方式选择**：比较 A/C/I、累计/分配、场内/场外等实际成本。
6. **净值序列计算**：用 CSV 程序化计算一只或多只基金的风险收益指标。

记录投资目标、预计持有期、最大可接受回撤、流动性、基础币种/汇率承受力、税务或账户限制。用户未提供时继续做产品级研究，但不要声称“适合你”。

## 3. 确认每只基金的身份

从基金公司、基金合同/招募说明书、监管或交易所页面确认：

- 全称、代码、份额类别、交易所或销售渠道
- 对国内基金核对六位代码、场内/场外代码、ETF/联接关系和 A/C/E/I 等份额生效日期
- 注册地、币种、成立日、规模及规模日期
- 基金类型、主动/被动属性、目标和正式基准
- 申赎/交易规则、费率、分红、锁定和业绩报酬

同名、跨市场代码、A/C/I、Accumulating/Distributing 等有歧义时先消除歧义。比较份额时使用同一底层组合，并计入投资者真实可获得渠道的全部费用。

## 4. 收集与校验证据

按以下优先级取证：

1. 监管/交易所披露、基金合同、招募说明书、定期报告
2. 基金公司事实表、持仓、费率和经理公告
3. 指数公司方法书与指数数据
4. 独立且信誉良好的基金数据库
5. 权威媒体；只用于事件背景和外部观点

国内基金按 `china-fund-guide.md` 的来源顺序执行：基金管理人、证监会/法定披露、沪深北交易所和指数公司优先；第三方平台的估算净值、实时持仓、风险等级和同类排名不得直接当一手事实。

关键事实至少使用一项一手来源；规模、费率、经理任期、收益序列、基准和持仓尽量独立复核。两个页面若转引同一供应商，不算两个独立来源。来源冲突时解释日期、币种、份额、复权和净/毛费率口径。

为动态数据分别记录“数据截至”和“获取日期”。不要把不同日期的规模、持仓和收益拼成同一时点快照。

最低证据集：

- 策略、基准、份额与费用
- 至少 3 年、优先 5 年及成立以来总回报；历史不足则用全部历史
- 正式基准和合理同类在相同期间、币种、频率下的表现
- 最大回撤、波动率、滚动表现和相关压力期
- 当前经理任期；把现任任期与完整基金历史分开
- 最新披露持仓、报告期、披露日、覆盖率、集中度和主要暴露
- 近期经理、策略、基准、费率、规模、合并清盘或监管变化

### 4.1 必要时使用 GLM-5V-Turbo 识图

优先解析官方 PDF 文本、HTML、CSV 和表格。只有用户持仓截图、扫描版报告或无法结构化提取的图表才使用识图。

先把相关页面或截图复制/渲染为任务输出目录内的 PNG/JPG；单批不超过配置的 `image_limit`。读取本 Skill 后必须调用动态工具 `skill__evaluate_fund__extract_evidence`，传入 `output`、`images`、`mode`，可选传入 `context` 或 `context_file`。

这是本 Skill 唯一的持仓识图入口。入口脚本和参数映射以同目录 `skill.toml` 为唯一事实源；不要另写临时 API/OCR 脚本，不要猜测脚本名、Python 路径或配置结构，也不要把任务误路由到通用 `glm5v-multimodal`。专用工具失败时按其真实错误修正结构化参数；不得退回 shell 手写脚本命令。

结构化字段 `mode` 可选 `portfolio-screenshot`、`fund-document`、`fund-chart`。工具复用股票分析 Skill 的 GLM-5V-Turbo 请求实现，包括 Bearer 鉴权、`stream=true`、`thinking=enabled`、SSE 聚合与重试；默认先找本 skill 的 `config.toml`，再找 `skills/glmv-stock-analyst/config.toml`。API Key 只从所选配置文件读取，不读取环境变量；不得读取/打印配置中的 Key，不得把 Key 写进命令、脚本或产物。抽取任务把补充上下文限制为 20,000 字符、模型输出限制为 16,000 tokens。动态入口超时为 `1500000` 毫秒。

脚本在写文件前对整批图片和所有 observation/unreadable/warning 预检并汇总问题。`raw_value` 保留原文和原单位；单位只在同字段表头/标签中出现时，用 `unit_source` 逐字记录来源。只有单一百分比可填写 `normalized_decimal`，脚本会复算核对；区间、金额、股数及其它单位必须为 `null`，`currency_or_unit` 必须完整保留万/亿等数量级。持仓截图中，单条数值的单位既不在 `raw_value` 也无 `unit_source` 证据时，仅清除该条单位/归一化值并降为低置信度，不丢弃其它可用持仓；其余预检错误只允许模型按错误清单修复一次，仍失败就停止。识图 JSON 只是转录辅助，不是独立来源。重大金额、比例、代码、报告期和持仓回看原图并尽量用官方文本复核；低置信度或不可辨认内容保留为缺口。GLM 配置/依赖不可用时继续使用已取得的结构化证据，并明确图片未能解析，不编造。

本地识图输入仅支持 JPG/JPEG/PNG，单图不超过 5 MiB，宽高均不超过 6000 像素；上传前会核对文件头与尺寸。

## 5. 执行多基金比较

对每只基金使用同一证据字段和报告结构。2–8 只基金时，可在 Agent/Task 工具可用的情况下按基金并行收集；每个结果必须自带来源、时点、缺口和红旗，再统一汇总。更多基金先做低成本初筛，再对候选深度研究。

比较前统一份额、币种、共同区间、频率、总回报和合理基准。目标不同的基金可以比较“组合作用”，但不能用一个总分横向排名。

同一 CSV 包含多只基金净值时调用 `skill__evaluate_fund__compare_funds`：

```json
{"csv_path":"nav.csv","fund_cols":["fund_a","fund_b","fund_c"],"benchmark_col":"benchmark","risk_free_rate":0.02,"output":"metrics.json"}
```

未可靠取得无风险利率时省略 `risk_free_rate`。输出比例都是小数，`0.125` 表示 `12.5%`。

`skill__evaluate_fund__calculate_fund_metrics` 和 `skill__evaluate_fund__compare_funds` 会在计算前扫描全部数据行，一次汇总日期、净值、基准、重复日期和缺失公共值问题；修正完整清单后再重调对应工具。

只有待比较基金适用同一基准时才传 `benchmark_col`。目标或正式基准不同的基金省略共同基准列，再分别调用 `skill__evaluate_fund__calculate_fund_metrics` 对各基金及其自身基准计算相对指标；不要为了生成统一表格而强套一个基准。

汇总时回答：

- 各基金提供的暴露和收益来源有何不同？
- 扣费后谁更有效交付目标，代价是什么？
- 谁在什么市场情景下更可能占优或失效？
- 基金之间的底层证券、行业、风格和经理风险是否重复？
- 共同区间的收益相关性是否支持真实分散，样本是否足够？
- 对不同目标/期限/回撤承受力，分别适合哪只或何种组合？

## 6. 研究股票型基金的底层持仓

先取得最新可验证的基金定期报告或基金公司持仓，不把聚合网站的“当前持仓”标签当实时事实。记录报告期、披露日、前十大覆盖率和完整持仓是否可得。

至少研究：

- 前十大股票
- 单只占基金净值 5% 以上的股票
- 在用户组合中被两只以上基金重复持有的股票
- 穿透后占用户总组合 3% 以上的股票
- 存在重大监管、财务、治理、估值或流动性红旗的股票

对每只重点股票核验业务与行业、收入/利润/现金流趋势、负债与财务健康、估值口径、近期重大事件、核心风险和反面证据。优先使用公司/交易所披露；可按需读取 `skills/ai-berkshire/skills/financial-data.md`、`quality-screen.md` 或 `investment-research.md`，但不要为每个小仓位机械生成完整个股长报告。

形成加权判断：底层公司质量、估值风险、行业集中、共同因子、单一事件风险和持仓披露滞后分别如何影响基金。旧持仓只能说明披露时点，不得声称是基金当前实时仓位。

## 7. 分析用户当前持仓

优先取得每只基金的市值或组合占比；若只有份额和现价，先计算市值。不要混用用户成本占比和当前市值占比。

把标准化数据写成 `portfolio.json`，格式见 `portfolio-analysis.md`，再调用 `skill__evaluate_fund__analyze_portfolio`：

```json
{"portfolio_json":"portfolio.json","output":"portfolio-analysis.json"}
```

组合脚本会先遍历全部基金、持仓、暴露映射、目标和限制并统一报告可独立发现的错误，不会在第一只坏基金或第一条坏持仓处停止。

必须展示：

- 基金类型、资产类别和现金占比
- 行业、板块、地区、币种
- 大盘/中盘/小盘，价值/均衡/成长等风格
- 久期、信用、权益 beta、汇率、商品、流动性等可识别风险标签
- 基金经理、基金公司、指数/策略集中度
- 底层证券总暴露、重复持仓、未知/未披露比例
- 单基金、前三大基金和底层证券集中度

将脚本结果与用户给出的 `targets` 和 `limits` 对照。建议使用“调整方向 + 渠道匹配的具体动作 + 当前值与建议区间/目标值 + 理由 + 优先级”，不要凭空给精确到个位百分点的最优配置。区分：

- **产品问题**：即使组合缺少该暴露，也不应继续持有的基金。
- **组合问题**：基金本身合格，但与其他持仓重复或权重过高。
- **投资者不匹配**：产品和组合都合理，但不符合期限、回撤或流动性要求。

将涉及当前持仓的每项建议绑定到已核验的具体产品：逐只写明基金全称、六位代码、份额类别和场内/场外身份，一只当前持仓占一行；不得只用“A50”“中证500”“A500”或基金公司名指代持仓。为每行同时给出与交易渠道匹配的唯一动作、当前占比或金额、建议区间或目标金额、理由、前提/成本和优先级，不要把“赎回/卖出”等候选动作原样留给用户选择。合并、替换或降低基金公司集中度时，把每只来源基金和目标基金拆成独立行。仅对产品未选定或身份未核实的行标记“候选待筛选”或“身份待核对”，不得虚构产品或给出确定交易指令；已核验来源基金的独立调整理由仍成立时，可给出条件和成本明确的动作。详细格式按 `portfolio-analysis.md` 和 `portfolio-report-template.md` 执行。

**交易建议证据闸门：** 当前持仓的产品身份没有逐只核验，或没有有效运行
 `skill__evaluate_fund__analyze_portfolio` 时，不得虚构产品级交易指令；先标记身份/暴露缺口，并给出核验后的条件式动作。已经核验的持仓和独立成立的产品问题仍应明确写出渠道匹配动作、理由与优先级。

**个性化参数不得阻断建议：** 用户明确询问如何操作时，即使尚未提供目标、期限或最大可接受回撤，也不得只回复“信息不足”或只罗列问题。先说明采用的中性默认假设，再对每只已核验持仓给出明确的持有、暂停加仓、分批赎回/卖出、合并、替换或新增方向，以及优先级、依据、成本和触发条件。缺少这些参数只限制精确交易金额、精确目标比例和整体股债/现金配置；相关数值使用区间或多情景方案，并在可执行建议之后用不超过三个问题收集信息以调整幅度。

## 8. 计算单基金净值指标

用户提供一只基金 CSV 时调用 `skill__evaluate_fund__calculate_fund_metrics`：

```json
{"csv_path":"nav.csv","date_col":"date","fund_col":"fund","benchmark_col":"benchmark","risk_free_rate":0.02,"output":"metrics.json"}
```

执行前确认基金列包含分红再投资，基金与基准同币种、同频率且日期对齐。不混用不同份额、未复权与复权净值，不推算缺失或成立前数据。

货币基金不得直接使用长期稳定在 1 附近的单位净值；应使用每日收益再投资形成的总回报指数或可核验收益序列。公募 REIT 和分红型基金同样要把现金分派计入总回报。

## 9. 评分与结论

按 `methodology.md` 的类型分支检查策略兑现、风险来源、费用和红旗。至少给出一个支持证据、一个反面证据或失效条件。

只有比较同类型、同目标、同口径产品时才使用 100 分制。披露权重和证据；缺失权重达到 20% 时不输出总分。硬红旗不能被高分抵消。

单基金结论使用：**适合 / 有条件适合 / 暂不适合 / 信息不足**。

持仓组合结论使用：**整体健康 / 基本合理但需调整 / 暴露失衡 / 信息不足**，并回答：

1. 最应该做的一件事
2. 最大集中风险
3. 最需要补足或降低的暴露
4. 重新评估触发点

不要给保证收益、确定性涨跌预测或证据不支持的买卖时点。

## 10. 生成并投递报告

完整分析、持仓分析或外部 channel 请求必须生成 `report.md`。按对应模板写完并完成质量检查后调用 `skill__evaluate_fund__render_report`：

报告中的图表先保存到 `report.md` 同目录或其子目录，再用相对路径引用。外部 channel 模式会内嵌这些本地图片；不要直接引用远程图片 URL。
RClaw 会向专用工具注入当前真实来源 channel；所有外部 channel 共用同一媒体沙箱，不要在参数中手填或猜测 channel。

```json
{"output_html":"<output_dir>/report.html","input":"<output_dir>/report.md","title":"基金评估报告"}
```

专用工具会直接捕获 stdout/stderr；不得退回 shell 包装脚本调用。

读取 stdout：

- `OUTPUT_HTML=` 给出 HTML 绝对路径。
- RClaw 会按 HTML、MD 的输出顺序校验每个 `MEDIA_MARKER=`，并自动把有效标记保留到最终出站消息；不得手抄或手写 marker。

按通道处理：

- 已使能外部 channel（如 `weixin`、`napcat`/`napcatqq`）：脚本生成图片内嵌的自包含 HTML，并把 HTML+MD 复制到媒体目录后打印两个媒体标记。不要自动发送 PDF。
- `cli` 且非 daemon：生成本地 HTML；可按平台打开浏览器，或直接返回路径。
- daemon、system、未使能 channel，或缺少 `RCLAW_MEDIA_DIR`：只返回 `report.html` 与 `report.md` 路径，不伪造媒体标记。
- 只有用户明确要求 PDF/DOCX 时，才调用相应文档能力另行导出。

聊天正文先给一句话结论、最大风险和最重要动作，再说明报告文件；不要把完整报告重复粘贴一遍。
