# 国内基金全市场筛选

从可证明覆盖范围的基金全集开始，逐层缩小到值得深度研究的候选。筛选结果是研究队列，不是买入指令。

## 路径与依赖

- 启动前本 skill 部署到 `agent/skills/screen-funds/`；RClaw shell 默认 cwd 是 agent 根目录。
- 读取本 Skill 后调用 Manifest 动态激活的专用工具；不要自行选择解释器、脚本路径或参数。
- 把运行产物写到 `fund_screen_output/{任务名}_{YYYYMMDD_HHMMSS}/`，不要写回 skill 目录。
- 本 skill 负责建池和初筛。入围基金的产品核验、底层持仓、用户适配和最终判断使用 `skills/evaluate-fund/`。
- 完整报告先读取 `skills/evaluate-fund/SKILL.md`，再用其 `skill__evaluate_fund__render_report` 生成 HTML 和外部 channel 媒体标记。

## 核心约束

- 只有 manifest 的来源、快照日、预期份额数和预期策略数与标准化 CSV 一致时，才称为“全市场”。
- 以六位基金代码表示具体份额，以 `strategy_id` 合并同一组合的 A/C/E/I、场内/场外等份额；每个策略仅一个 `ranking_share=true`。
- 只在可比 `cohort` 内排名。类型、投资目标、基础币种、正式/分析基准或关键风险来源不同就拆组。
- 不把近一年涨幅、平台星级、销量、热度或估算净值设为通用入围条件。
- 每层保留基金、状态、缺失数据和淘汰理由；不只输出赢家。
- 缺失指标进入 `insufficient_data`，不当作通过，也不默认为最差产品。
- 百分位分数仅表示当前快照下的同组相对位置，不表示预期回报或跨组质量。

## 1. 明确筛选任务

记录：投资目标、预计持有期、最大可接受回撤、流动性、基础币种、可购买渠道、是否只看 ETF/主动/固收等类型，以及要排除的产品或风险。

用户只说“全市场选基金”时，默认覆盖中国境内公募基金的存续份额，再按主要类型建立多个 cohort；不要生成一个跨类型总榜。若用户目标不明，先产出分类候选，不声称“最适合你”。

## 2. 加载参考

- 每次读取 [references/data-contract.md](references/data-contract.md)，按其中 schema 建立 manifest、CSV 和 config。
- 每次读取 [references/screening-methodology.md](references/screening-methodology.md)，选择类型分支、硬过滤和评分指标。
- 生成报告时读取 [references/report-template.md](references/report-template.md)。
- 深评入围基金时再读取 `skills/evaluate-fund/SKILL.md` 及其对应方法文件。

## 3. 构建基金宇宙

优先从监管/法定披露、基金管理人和沪深交易所建立产品身份，再用有授权且可追溯的基金数据库补充批量字段。保存下载文件或查询结果原始快照，不把搜索结果页、销售平台榜单或单一指数成份当全市场。

建立 `universe-manifest.json`：

- `scope=all-market` 时写明预期份额数、策略数和允许的枚举源最大陈旧天数；无法独立确认计数就改为 `subset`。
- 每个来源记录发布主体、原始定位、本地快照文件、快照 SHA-256、职责、数据截至和获取日期；动态筛选工具会复算哈希，全市场至少有一个 `universe-enumeration` 枚举来源。
- 合并后逐份额保留来源 ID；未被 manifest 登记的来源不能进入标准化表，全市场每行必须追溯到枚举来源。
- 当前选基宇宙可以只筛存续产品，但原始快照应保留终止、合并或清盘状态，防止审计时丢失。

## 4. 标准化和分组

把一行定义为一个具体基金份额。核对六位代码、名称、份额、策略 ID、成立日、状态、币种和数据日期。`metrics_as_of` 使用本行所有动态筛选字段中最早的截至日，并由所引 `metrics` 来源覆盖；不要把不同日期拼成同日快照。只有身份记录的终止/合并产品可把它留空，脚本会保留该行但禁止排名。比例统一用小数，`0.012` 表示 `1.2%`。

为每个策略指定一个历史连续、数据完整且能代表底层组合的排名份额。其余份额仍留在 CSV，后续按持有期、渠道费率和场内流动性选择，不得重复占据候选榜。

`cohort` 至少编码基金类型/策略、币种和可比目标或基准。例如：

- `主动权益|CNY|中证800类`
- `沪深300ETF|CNY|沪深300全收益`
- `中长期纯债|CNY|纯债类基准`

QDII、FOF、货币基金、公募 REIT、商品及短历史基金使用独立 cohort 和指标，不能硬套主动权益评分卡。

## 5. 配置筛选漏斗

在 `screen-config.json` 中显式写出：

1. **硬过滤**：产品状态、身份完整性、数据新鲜度、历史长度、规模/流动性底线、申赎状态或用户禁区；类型专属规则用 `cohorts` 限定。
2. **评分卡**：每个 cohort 的字段、方向、权重和必要的数据有效范围。
3. **样本门槛**：`minimum_cohort_size`；样本过少只列数据，不排名。
4. **候选数量**：`top_n_per_cohort`；截止分数并列时全部保留。

需要不同样本或候选数量时用 `cohort_settings` 覆盖全局默认。阈值必须说明理由和适用类型。规模、成立年限或经理任期不足可以进入观察组；除非用户明确要求，不要把年轻基金自动判成差基金。

## 6. 运行确定性筛选

调用 `skill__screen_funds__screen_universe`：

```json
{"universe_csv":"universe.csv","manifest":"universe-manifest.json","config":"screen-config.json","output":"screening.json"}
```

脚本会：

- 在计算前批量预检 manifest、config、所有来源、快照和 CSV 行，一次列出可独立发现的全部问题；
- 校验全市场计数、原始来源快照哈希、代码、日期和策略/份额去重；
- 执行硬过滤并记录每条失败原因；
- 在 cohort 内计算加权百分位分数和并列排名；
- 输出 shortlist、全量 `audit_rows`、各状态计数及三个输入文件的 SHA-256。

脚本失败时按预检清单修正整批宇宙或配置，不用手工删除失败行绕过校验。

## 7. 复核候选与淘汰样本

至少执行以下检查：

- 抽查每个 cohort 的入围、临界淘汰、硬过滤淘汰和数据不足样本。
- 比较不同时间窗、权重和合理阈值下候选是否稳定；只在单一参数下胜出的基金降级。
- 检查幸存者偏差、份额重复、基准错配、经理变更、规模容量、申赎限制和披露滞后。
- 对排名异常高的基金核验是否由短历史、净值平滑、货币/汇率错配或单次极端收益造成。
- 入围过多时增加研究层证据，不为凑固定数量随意抬高阈值；没有足够好候选时允许空缺。

## 8. 深评与最终选择

每个主要 cohort 通常保留 3–10 个候选，再使用 `evaluate-fund`：

- 确认产品、份额、基准、费用、经理和最新重大变更；
- 重新计算共同区间风险收益；
- 对股票型基金检查底层股票、行业和风格；
- 与用户当前持仓做重叠和适配分析；
- 给出支持证据、反面证据、失效条件和数据缺口。

初筛分数不能覆盖深评硬红旗。最终报告区分“筛选排名”“产品判断”“用户适配”，不把三者合并成一个分数。

## 9. 生成报告和外部投递

按模板生成 `report.md`，至少包含宇宙覆盖、漏斗计数、分类候选、淘汰原因、稳健性检查和待深评清单。需要 HTML 或外部 channel 时，先读取 `skills/evaluate-fund/SKILL.md`，再调用 `skill__evaluate_fund__render_report`：
RClaw 会向专用工具注入当前真实来源 channel；所有外部 channel 共用同一媒体沙箱，不要在参数中手填或猜测 channel。

```json
{"output_html":"<output_dir>/report.html","input":"<output_dir>/report.md","title":"基金全市场筛选报告"}
```

按 `evaluate-fund` 的约定读取 `OUTPUT_HTML=`；RClaw 会校验脚本 stdout 中的 `MEDIA_MARKER=` 并自动保留有效标记，不得手抄或手写 marker。没有有效 marker 时只返回本地文件路径，不得声称已发送。

## 质量闸门

- [ ] manifest 能证明所称范围，计数与 CSV 完全一致
- [ ] 六位代码为字符串，同策略份额没有重复占榜
- [ ] 每个 cohort 的类型、目标、币种、基准和风险来源可比
- [ ] 总回报、费率、规模、经理和基准字段注明日期与口径
- [ ] 硬过滤和权重有理由，不使用热度或短期涨幅替代质量
- [ ] 缺失数据、未排名、硬淘汰和非排名份额均保留
- [ ] 候选通过参数稳定性和正反样本抽查
- [ ] 入围基金已进入 evaluate-fund 深评，初筛未被写成买入建议
- [ ] 报告记录来源快照 SHA-256、是否完成复算、三个输入文件 SHA-256、运行日期和局限性
